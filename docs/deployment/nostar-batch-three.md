# NoStar 第三批：仓库身份与上游修复

仓库使用 GitHub 数字 ID 作为身份。同一个 ID 改名时更新原记录；不同真实 ID 即使复用同名，也不共享 AI 分析、分类或订阅。

早期批量 Star 留下的时间戳 ID（`>= 100000000000`）仅在仓库名称对应唯一真实 ID 时认领。认领后立即使用真实 ID，原子更新浏览器中的 Release 引用、订阅、展开状态及相似结果，并保存新 ID 的分析快照。多条真实身份共用名称时，保留无法确定归属的旧记录，不任选目标。

服务端同步与导入共用身份整理：直接更新旧行的 GitHub ID，保留数据库主键及 Release 外键；已经存在真实 ID 的双记录先迁移 Release 外键，再折叠旧行。旧基线一并转换到真实 ID，再执行字段级三方合并，保留其他设备的编辑及删除。已认领的旧 ID 映射存于按用户隔离的内部设置，旧备份在仓库改名后仍能识别，不重新创建时间戳记录。内部映射不出现在设置响应或导出中，不接受设置更新或导入覆盖。

数据库备份保留历史 ID 映射；JSON 导出只包含当前规范 ID，不携带内部映射。因此 JSON 跨数据库恢复后，来自更早客户端或备份的旧时间戳 ID，在名称也已变化时无法自动确认原身份。

## 数据迁移

迁移 `20261026203000_nostar_repository_identity` 将 `NoStarRepository(userId, fullName)` 唯一索引改为普通索引。`(userId, githubId)` 唯一约束不变；无需重写现有仓库或 Release 数据。允许名称历史暂时冲突，避免同步顺序导致唯一约束失败。只有名称的旧 Release 引用遇到多个候选时跳过，带仓库 ID 的引用始终按身份解析。

部署前生成 Prisma 客户端，按现有流程执行迁移。迁移不删除数据；回滚唯一索引前需要先解决同用户下的重复名称。

## 上游适配范围

身份规则参考 `b3e8a14` 至 `0b2ff27`，保留 NoNo 会话、PostgreSQL 和按用户数据隔离。README 与 WebDAV 的改进单独按当前 Web 组件和受控服务端代理适配。当前集成没有使用被移除的 `Repository.openIssues` GraphQL 字段，无需迁入上游 `fea5e9d` 的查询修改。

本批核对范围为上游 `155d715..aa1e3c7`（包含 v0.8.7），按适用性移植修复，不表示完整合并上游所有功能：

| 上游提交 | 当前集成的适配 |
| --- | --- |
| `8f81ad8`、`3b0d837` | WebDAV 207 目标资源状态检查；HEAD/PROPFIND 共用 10 秒截止时间；文件探测兼容 405/501 回退 |
| `7795647`、`095c83a` | Markdown 图片逐项过滤 srcset，保留 picture 的直接 img/source 子元素，继续约束协议与 HTML 清理 |
| `65c8429` | 图片预览和下载使用浏览器实际选择的 currentSrc，失败时保留原有回退 |
| `33dba3d` | README 弹窗接近全屏，保留键盘、焦点和关闭行为 |

上游 Electron、插件、部署向导和独立 Express 服务端变更不直接移入集成版；AI 语义搜索新功能也不属于本批修复。网络请求继续使用现有的服务端 DNS 校验、地址固定及逐跳重定向策略，不开放上游允许私网访问的选项。相关依赖补丁通过本项目各自的锁文件升级。

Mermaid 保留最新 11.x（11.17.2）：12.2.0 自动引入的 ELK 异步分块约 440 KiB gzip，超过现有 180 KiB 单块预算。11.x 通过当前安全审计及图表测试，不放宽预算；KaTeX 安全版本覆盖保留在锁文件中。

## 验证

新增回归覆盖合成 ID 认领后改名、名称复用、双记录折叠后的 Release/已读/订阅/展开状态、旧备份恢复、并发字段编辑，以及名称歧义时不跨身份复制数据。运行 NoStar 身份、Store 与 Star 同步测试、TypeScript 检查，以及服务端 NoStar 路由、身份和许可证测试。未对用户真实 GitHub 收藏或 Lists 执行写操作。

根任务在临时 PostgreSQL 18.4 数据库运行完整集成脚本，包含 NoStar 真实行重键、外键与已读状态保留、旧基线并发合并、改名后的旧备份及名称复用场景。数据库测试目标为可重置的本地专用库，未连接生产数据。
