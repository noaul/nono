# NoNo Android 应用设计草案

状态：v0.1 在线外壳已实现（`apps/android`，对应计划 Task 1 及 Task 4 的简化分享入口：分享后预填书签页，暂未做幂等收藏接口）；推送等后续任务未开始。日期：2026-10-02。

## 目标与默认范围

为个人日常使用提供一个连接 `https://noaul.com` 的 Android 应用，在小米澎湃 OS 4 目标手机上验证收藏、资产查看/编辑、服务器状态和通知。首个可用版本侧重在线业务；可靠后台推送作为后续独立验收里程碑。原生侧负责系统交互，现有 Web 页面及 nc48 后端负责业务。

默认一台手机、一个当前账户、固定站点、中文优先、签名 APK 侧载。实现仍必须按账户授权，不把“个人使用”转化为共享管理员凭据。多站点、全原生重写、离线财务编辑、应用商店发布另行安排。

## 全局约束

- 生产站点固定为 `https://noaul.com`；调试服务地址仅可通过 debug 构建配置提供。
- 登录复用 NoNo 浏览器会话；保持 HttpOnly、Secure、SameSite、Origin 校验和现有权限边界。
- APK 不携带管理员密码、NoNo 内部调用令牌、小米服务端推送密钥或签名私钥。
- WebView 只承载受信任站点；原生消息桥仅允许精确来源、主框架及列举的消息类型。
- 普通业务数据仍以服务器为准；v0.1/v0.2 不提供离线编辑或自动提交财务操作。
- 小米推送资格、完整 ROM/Android/WebView 版本和签名包名必须在推送正式开发前验证。
- 所有移动功能新增数据库迁移采用加法迁移；生产发布沿用现有备份、维护、验收流程。
- 通知日志区分排队、厂商受理、终端回执和用户打开；无回执时终端送达为未知。
- 账号退出/撤销后禁止新推送投递；已交给厂商的在途消息不能承诺撤回。
- 支持版本、依赖及 targetSdk 在任务 0 按当时稳定工具链锁定，不由“澎湃 OS 4”名称推断 Android API 等级。

## 方案选择

采用 Kotlin、AndroidX Activity/WebKit、单 Activity + 单 WebView。原生 Compose 仅用于离线/错误界面和应用设置，不重建五套业务界面。页面之间切换继续在同一 WebView、同一 Cookie 存储中完成。

比较方案：PWA 对分享、下载和系统推送的控制较弱；Capacitor 可以承载远程页面，但本仓库含 Next.js 服务端能力和多个前端栈，本地打包及跨源认证增加首版工作量；Flutter/React Native 重做五套页面的成本更高。当前需求下，Kotlin WebView 首版最直接。

## 用户流程

1. 安装并启动：连接站点，打开 `/nodesk`；需登录的操作跳转 NoNo 登录页并保存安全的站内目标。
2. 日常使用：今日概览、书签、NoMoney、Yumi、NoStar 共用一次登录。手机模式使用一套页面导航；不叠加两套原生和网页底栏。
3. 从其他应用分享：系统“分享 → NoNo”→ 本地保存临时待收藏内容 → 登录（如需）→ 选择文件夹、编辑标题 → 明确确认保存。识别多个网址时让用户选择，不自动猜测或提交。
4. 收到提醒：默认只显示“有一条新的 NoNo 提醒”；点击打开站内通知入口，校验登录和归属后加载详情。
5. 退出：在线撤销会话及设备绑定，清理本机通知、认证 Cookie、临时分享和敏感页面历史；离线先完成本机退出，排队重试仅可撤销设备的请求。

NoDesk 现有任务/日程未按账户划分 localStorage。APP 退出前要明确提示未同步本机数据将被清理，允许取消退出；P2 文件功能完成后提供先导出再退出的选择。不能让下一账户看见前一账户数据，也不能默默丢失未同步任务。跨设备同步上线后再简化此步骤。

## Android 与 Web 边界

Android 提供导航拦截、返回、键盘与安全区、系统分享、文件选择/保存、通知权限及渠道、推送接收、版本信息与错误恢复。Web 页面继续使用现有认证 API 和业务表单。

新增版本化消息协议 `v: 1`，消息均有 `requestId`。方法仅包括 `capture.ready`、`capture.saved`、`push.registration`、`ui.backState`、`ui.back`、`session.signedOut`、`localData.export`。所有消息校验精确来源、主框架、类型、长度及请求状态；`localData.export` 仅允许用户主动导出符合限定 schema、1 MiB 内的本机任务/日程，其他消息限 16 KiB。桥不提供任意 HTTP 请求、文件读取或脚本执行能力。`client=android` 只控制呈现，不能代表登录或提升权限。

返回顺序：关闭可见弹层/选择器 → 当前页面路由返回 → WebView 历史返回 → 根入口退出。预测性返回在手势提交后改变状态，取消手势不导航。页面生命周期变化和进程重建不重发写请求。

下载仅接受明确允许的站内 HTTPS 下载地址，逐跳校验重定向；认证 Cookie 不传给外站。流式保存到用户通过 Storage Access Framework 选择的文件，支持取消和清理半成品。首版把实际使用的 blob 导出改为站内下载接口或受限流式导出，禁止不设大小限制的 base64 桥。

## 认证与设备绑定

首版使用密码登录并保留站点 Passkey 页面。WebView Passkey 单独验证 Credential Manager、凭据提供器和站点关联，成功才作为支持功能列出。APK 的 WebView 与手机浏览器不会自然共享会话。

Android 产生随机 installationId，向信任页面提交厂商 registrationId。页面通过同源 fetch 调用 `/api/mobile/devices`；服务器从浏览器会话取得 userId/sessionId，不接受客户端指定所属用户。首版设备绑定随会话有效期（目前 14 天）失效，重新登录后重新绑定；界面应能说明手机提醒的绑定状态。

设备记录保存 token 的加密值和用于唯一约束的哈希。发送前连接查询当前用户、有效会话及设备状态。会话删除通过外键使绑定失效，并覆盖退出、撤销其他会话、改密和用户删除。离线撤销用单独的随机撤销凭据，只允许撤销本设备、不能读数据或重新绑定；明文仅保存在 Android 私有存储并由 Keystore 保护。

## 推送与可靠性

nc48 生成业务事件，持久化事件及每个设备的发送任务，再由后台工作进程调用小米推送。前台刷新通知列表补齐展示。无需 APP 保活，也不以 WorkManager 周期轮询实现实时提醒。

现有 NoMoney/Yumi relay 每次调用使用随机 UUID，现有普通通知按 5 分钟扫描。接入手机前为可重试的源事件提供稳定 eventId：资产提醒按资产、到期日、提醒档位标识；状态告警使用已持久化的告警事件标识。相同事件重复入队只产生一个设备任务；来源业务事务未提交前不入队。旧调用方无 eventId 时保留原行为，不宣称消除了全部历史重复。

手机 outbox 与邮件/Telegram/Bark/Webhook 分开记录，避免某一通道成功导致另一路被遗漏。允许只有手机设备、没有旧渠道时发送。产品 relay 在手机任务持久化成功后可返回“已接收”，旧渠道的失败继续由各自任务或原重试规则处理；界面不把入队显示为已送达。

可重试错误采用 30 秒、2 分钟、10 分钟、30 分钟、2 小时退避并受 TTL 限制；无效 token 禁用设备；认证/配置错误停止无效重试并报告。每个 `(eventId, deviceId)` 唯一。数据库租约防止多个 worker 同时领取任务；进程在厂商受理后崩溃可能导致重试，利用厂商去重键（若支持）和终端通知 ID 降低重复，不承诺端到端 exactly-once。

首版告警有效期 1 小时，到期提醒及普通通知有效期 24 小时；厂商端 TTL 不超过剩余有效期。故障恢复或到期事项已处理时，取消尚未投递的失效事件，避免网络恢复后收到过时告警。

通知默认不含资产名称、金额、账号、服务器地址；事件引用也不授予读取权限。SDK 只有受理信息时，日志只记 accepted；收到可信且可关联的终端回执才记 received，用户点击才记 opened。

## 验收与后续

v0.1：安装、登录、五个入口、基本导航和维护/离线恢复在目标手机通过。

v0.2：分享收藏、文件操作、通知设备生命周期和可靠推送在目标手机通过；另做至少 48 小时日常使用测试。强行停止、通知权限关闭、无网络分别记录为受限制状态，不能计作“任何情况下保证到达”。

v0.3：再规划服务端任务/日程同步、Passkey 完整支持、小组件和只读缓存。离线编辑需独立的数据同步设计，不在当前实施计划中预先引入第二套业务数据库。
